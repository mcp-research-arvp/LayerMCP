## What comes from research sources

- The issue text is mechanically extracted from the released initial user
  prompt.
- `instance_id`, source model, exit status, source coordinate, success flag,
  action order, exact fenced commands, and environment observations come from
  the pinned dataset.
- The selected rows are successful released model trajectories, not gold
  human programs and not manually authored LayerMCP solutions.

The natural-language issues originate from real GitHub/SWE-bench-style tasks.
The action sequences were generated by models operating through a SWE-agent
interface. The dataset is therefore a mix of public issue content and synthetic
model behavior; it must not be described as a human-written tool-call corpus.

## LayerMCP adaptation

- Selection is deterministic: walk successful rows in pinned physical order,
  keep the first eligible trajectory for each distinct issue, and stop after
  500 issues.
- Benchmark membership applies a maximum of five calls per workflow without
  renumbering source-derived benchmark IDs. This retains 33 of the 500 selected
  workflows and 139 calls: four workflows with three calls, 18 with four calls,
  and 11 with five calls.
- The checked-in benchmark fixture contains exactly those 139 referenced call
  records. The other 6,866 calls are not copied into Git; the pinned source
  files and deterministic importer remain the reproduction path.
- Model discussion is omitted. Only the final fenced action in each `role=ai`
  message is parsed, classified mechanically, and paired with its following
  `role=user` environment observation.
- The source command families are mapped to five prefixed replay tools:
  shell, file view, file search, file edit, and submit.
- Replay coordinates (`record_id`, derived trajectory ID, and step index) form
  the complete runtime call schema, so state-dependent duplicate commands
  cannot resolve to the wrong observation. Exact source commands remain in the
  fixture and are returned as replay provenance rather than model-generated
  arguments.
- Observations are bounded to deterministic excerpts and full-output SHA-256
  values. Exact edit commands can include generated patch fragments, and
  bounded observations can include test-log excerpts; no complete generated
  workspace or full unbounded evaluation log is copied.
- Terminal `submit` is retained with an unavailable-observation sentinel when
  the released trajectory ends immediately after that action.
- No command, edit, test, package installation, or submission is executed.

The generated per-step instruction is a LayerMCP wrapper around the exact
source action. The workflow issue is not generated. The tool prefix,
coordinate arguments, action-family classification, and step wrapper are
mechanical benchmark adaptations.

## License and use boundary

The dataset card states that the release is CC BY 4.0 and separately asks users
to respect the license of each underlying repository. It also calls out
applicable Llama 3.1 terms for model outputs. This repository does not replace
those obligations. Users who redistribute or train on the adapted records
must review the source dataset card, the underlying repository license, and
the relevant model-output terms.

This adaptation evaluates teacher-forced action-family and replay-coordinate
routing while preserving exact released arguments in its benchmark fixture. It
does not run repository environments, validate patches, reproduce SWE-bench
test oracles, or establish autonomous issue resolution.
